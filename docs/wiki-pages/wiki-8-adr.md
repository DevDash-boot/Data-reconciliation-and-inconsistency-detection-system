### ADR-001: Strategy 패턴으로 비교 규칙 분리
- **관련 이슈**: #7
- **상황**: 금액만 비교, 금액+상태 비교 등 규칙이 늘어날 수 있다.
- **선택지**: (1) if/else 분기 — 빠르지만 규칙마다 엔진을 고쳐야 함 (2) Strategy — 구조가 약간 복잡하지만 엔진 불변
- **결정**: Strategy
- **이유**: 새 규칙을 클래스 하나 + 등록 한 줄로 추가. 엔진 테스트가 규칙과 분리된다.
- **결과**: 전략 2개로 시작. 퍼지 매칭 같은 규칙도 같은 인터페이스로 확장 가능.

### ADR-002: PK 를 IDENTITY 로 두고 대량 적재는 JDBC batch 사용
- **관련 이슈**: #3, #12, #13
- **상황**: MySQL AUTO_INCREMENT(IDENTITY)에서는 JPA `saveAll` 이 INSERT 를 묶지 못한다. (Hibernate 는 IDENTITY 에서 JDBC batch 를 끈다)
- **선택지**: (1) JPA saveAll 유지 (2) PK 를 SEQUENCE/TABLE 로 변경 (3) 적재만 JDBC batch
- **결정**: (3) 엔티티와 일반 CRUD 는 JPA 유지, 대량 INSERT 만 JDBC batch (`rewriteBatchedStatements=true`)
- **이유**: 10만 건 기준 (수치: baseline N초 → N초). MySQL 은 SEQUENCE 가 없어 (2) 는 TABLE 전략이 되어 오히려 느리다.
- **결과**: 같은 트랜잭션에서 JPA 와 JDBC 를 함께 쓴다. batch size 는 설정값(`recon.jdbc.batch-size`).

### ADR-003: 키 하나당 불일치 1건 + 유형 우선순위
- **관련 이슈**: #2, #8
- **상황**: 한 키에 중복과 값 차이가 겹치면 같은 문제가 여러 건으로 보인다.
- **결정**: DUPLICATE > MISSING_* > VALUE_DIFF 순으로 하나만 기록. DB 에서도 UNIQUE(job_id, match_key)
- **이유**: 중복이면 어느 행을 비교할지 모호하다. 운영자는 키 단위로 처리한다.
- **결과**: expected 건수 계산이 단순해지고 재실행 중복이 DB 에서 막힌다.

### ADR-004: 청크 분할은 CRC32 해시 파티션
- **관련 이슈**: #14
- **선택지**: (1) 키 범위 분할 — 키 분포를 모르면 쏠림 (2) 정렬 후 merge-join — 커서 2개 동시 관리 (3) 해시 파티션
- **결정**: 해시 파티션 (`MOD(CRC32(key), N)`)
- **이유**: 같은 키는 항상 같은 청크 → 경계 문제 없음. Java 와 MySQL 이 같은 값을 낸다. 균등 분포(테스트로 확인).
- **결과**: 메모리는 1/N. 대신 청크마다 batch 범위를 다시 훑는다. (수치: 측정 후)

### ADR-005: 멱등성은 active_key UNIQUE 로 보장
- **관련 이슈**: #16
- **상황**: 같은 요청이 중복/동시에 올 수 있다. FAILED Job 이 있어도 재실행은 가능해야 한다.
- **선택지**: (1) 애플리케이션 락 — 서버 여러 대에서 무력 (2) job_key UNIQUE — FAILED 이력이 재실행을 막음 (3) active_key UNIQUE
- **결정**: (3) PENDING/RUNNING/SUCCESS 동안만 job_key 와 같은 값을 갖고 FAILED 면 NULL (MySQL UNIQUE 는 NULL 중복 허용)
- **이유**: 동시 요청도 DB 가 최종 방어한다. 실패 이력은 남기면서 재실행 가능.
- **결과**: 서버 재시작으로 RUNNING 이 남는 문제는 시작 시 정리(`JobRecovery`).

### ADR-006: CSV 파서를 직접 구현
- **관련 이슈**: #5
- **선택지**: OpenCSV 등 라이브러리 vs 직접
- **결정**: 직접 (따옴표, "" 이스케이프, BOM, 행 단위 오류 수집)
- **이유**: 필요한 범위가 작고 의존성을 늘리지 않는다. 단위 테스트로 규칙을 고정했다.
- **결과**: 따옴표 안의 줄바꿈은 미지원 (이 데이터에는 불필요). 필요해지면 라이브러리로 교체.

### ADR-007: 상태값은 원본 저장, 대조 시점에 매핑
- **관련 이슈**: #2, #3
- **결정**: `source_*.status` 는 파일 값 그대로 저장하고 `paid → PAID` 매핑은 ScopeRules 에서
- **이유**: 매핑 규칙이 바뀌어도 데이터를 다시 올릴 필요가 없다.
